# Authenticated Evidence source adapter

`./evidence-source` exports `createEvidenceTextSource`, a source callback for the accepted single-job text worker. It calls the accepted Evidence facade, never its SQL or object root. The processing ledger retains its stable Evidence SQL SDK pin and its own separate database; the facade contract is a separately pinned dependency alias at Evidence PR3 source `c9aafd0cc7d655e4dc3f8b5b8b833ef102d4cf2b`.

The host supplies a managed Evidence credential callback and a mandatory current processing-policy callback. Read permission is not processing permission. Strict true processing authorization is checked before reads and again before returning bytes. Requests contain only the managed token and captured purpose/request ID; Evidence derives scope/roles from its current identity directory on each call. A supplied consumed snapshot is metadata, never authentication or a transferable permit; use this callback through the worker's acknowledged consumption path and a trusted host.

Inspection before and after the authenticated object read requires the exact job edition/hash/byte length, clean scan, permitted purpose and `text/plain` media type. The adapter copies and hashes the returned bytes, rejects aggregate revision drift and returns only the exact ProcessingInput. It supports at most the accepted 5MiB UTF8 worker budget. Other media types need separately qualified adapters.

One configurable 10–30000ms deadline (default 5s), monotonic checks and propagated cancellation bound acceptance and prevent later stages after errors. Errors are sanitized. Cancellation cannot undo reads, audits or integrity quarantine already begun; noncooperative calls may finish after timeout. Post-read inspection and final processing-policy checks are not a distributed atomic permission fence. Gateways must enforce current policy at the actual operation; no claim of permission remaining valid afterward is made.

Initial restricted-migration tests exercise the actual accepted authenticated facade, real temporary encrypted objects, a separate processing database, quarantine, identity revocation and a synthetic test-only scanner. This is not a real malware scanner, deployed identity/object service, network-session integration or live private-data acceptance. Storage/outcome/receipt gateways, daemon, liveness and production qualification remain pending. Additional review and final-head CI remain pending at this checkpoint.
