# PostgreSQL session contention

`npm run test:postgres` exercises the pinned Evidence SDK PostgreSQL driver and actual text-job ledger over separate authenticated TCP sessions. It is distinct from embedded PGlite tests. Six groups cover simultaneous consumption, a directly observed database lock wait followed by lease expiry, competing success/failure commits, and durable state after an intentionally lost post-COMMIT acknowledgement and fresh login/pool. The fifth checks rejection of privileged/lowered migration sessions, runtime schema/role denial, and scoped record visibility. The sixth checks competing retry managers, one deterministic successor and historical replay after that child has consumed its own permit.

The CI job owns a disposable PostgreSQL 17 service. Fixed fixture passwords are not deployment credentials. Tests require `DMP_TEST_DISPOSABLE_POSTGRES=1` and a loopback `DMP_TEST_ADMIN_URL` for the empty database named `processing_ci`; URL overrides/queries/remote hosts are rejected. If the ledger schema already exists, setup fails instead of resetting anything. The canonical SDK migration is applied inside the driver's transaction, removing only its outer BEGIN/COMMIT wrappers. A restricted non-owner LOGIN has only evidence_runtime membership; application actions authenticate as that login, never as the fixture migration administrator.

The lock test polls pg_stat_activity/pg_blocking_pids through a separate fixture administrator connection. It advances the controlled clock only after observing a genuinely blocked worker backend. It does not infer contention from sleeps or substitute a query mock. Fresh independent backend PIDs and session_user are asserted. Verifiers are explicit controlled fixtures; these tests do not attest real source permissions or receipt/liveness services.
