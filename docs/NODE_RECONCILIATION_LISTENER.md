# Direct Node TLS listener (partial DMP-005)

`createNodeReconciliationListener(handler, {origin, maxInFlight?, exchangeTimeoutMs?})` from `./node-reconciliation-listener` returns a Node HTTP/1.1 RequestListener for an independently provisioned HTTPS server. Pass the accepted `createIdentityReconciliationHandler` result as handler. The library opens no port, creates no credentials/certificates, issues no cookies and installs no public deployment. The host owns TLS/key custody, real session authentication and current policy. This is a transport bridge, not authentication.

Admission requires a directly encrypted TLS socket, HTTP/1.1, exact captured HTTPS authority/Host, origin-form request target and one of the existing /processing/session or /processing/reconcile paths with GET/POST. Unknown routes, duplicate headers, forwarded/proxy authority hints, upgrade/expect, malformed targets and declared oversize bodies are refused before handler entry. It does not trust forwarded headers or support a TLS-terminating reverse proxy/HTTP2. The accepted Fetch handler still enforces exact route method/query/Origin/Fetch Metadata, CSRF, purpose, manager/domain/current Identity policy.

The bridge checks at most 128 raw header pairs/16KiB after parsing. The listening host MUST separately bound TLS handshakes, connection count, socket/header timeouts and parser allocation (for example Node maxHeaderSize, headersTimeout and requestTimeout) BEFORE listener invocation. These limits are not supplied by this RequestListener. Incoming POST bytes/chunks are bounded to 16KiB/4096 with backpressure; rejected/cancelled reads stop consuming. Every response uses Connection: close, so an unread rejected body is not reused on that connection. Response JSON/media/no-store admission and actual 256KiB/4096-chunk limits apply; only fixed private JSON headers are sent, no arbitrary handler cookies/redirects/CORS. Successful normal request end does not imply client disconnect.

A per-instance in-flight cap (default16, range1..128) includes handlers still running AFTER disconnect/deadline. Default30s exchange timeout (10..60000ms) aborts the Fetch signal and returns a private unknown result if possible. Noncooperative handlers retain their slot until they really settle; the bridge does not abandon begun SQL/FS or grant another slot to substitute a new operation. A hung trusted handler can exhaust availability; host driver/worker limits and recovery remain necessary. Monotonic gates fence blocked-JavaScript overruns and late responses; callbacks cannot be preempted or effects undone.

Admission errors before handler entry return private400; failures AFTER handler entry and deadlines return503/unknown, never proof of rollback or absence. A disconnect may follow a durable commit. Existing HTTP acknowledgement semantics remain: retain the exact pending command and explicitly reconcile after fresh session/CSRF; do not automatically retry or switch operation. Client cancellation aborts admission and response acceptance, not a SQL rollback promise. Owned timers/signals/readers are closed; unread or late handler bodies are cancelled without awaiting hostile cancellation callbacks. Error diagnostics never include callback text.

The host must construct the handler and listener with the SAME exact origin and enforce current identity/session/purpose/logout/rate/concurrency controls. There is no binding from certificate metadata or Host header to an authenticated participant. Membership/Processing authorization remain sequential snapshots, not an atomic cross-service revocation/action fence or capability check. No new execution/retry/no-output/cleanup/download/send/publication routes are provided.

Six local groups and typecheck pass at this checkpoint. One actual loopback-TLS test executes current Identity membership plus separate restricted-migration Processing/Identity PGlite databases, AES-GCM private output finalization, byte preservation and subsequent stored disable denial. Five transport groups use controlled handlers for authority/proxy/route/header/body/response admission, normal body end, deadline/concurrency retention, disconnect/late results and sanitized errors. Tests create temporary self-signed localhost certificates with OpenSSL, trust ONLY that certificate as CA, verify hostname normally and bind only loopback. No rejectUnauthorized:false/checkServerIdentity bypass. Initial fixture DNS callback was corrected with family:4 for Node multi-address lookup; no certificate verification was disabled. Full local suite/installed compiled exports/current-head CI remain separate gates.

This adds actual local TLS transport evidence only for these scenarios. It does not qualify production certificates/PKI/login/cookies/proxies/browser/assistive technology, network database contention, host crashes, key/source/receipt/liveness services, failover/throughput/multinode or live investigative use. All fixtures are fictional; no provider or private input is used. PAM remains downstream.
