# Private text-output reconciliation HTTP adapter

`./reconciliation-http` exports createReconciliationHandler(jobs, outputs, authentication, policy, clock). The host supplies actual TextProcessingJobs/PrivateTextOutputs on the SAME Processing-owned operational database and private object root, a trusted authentication callback, and a live clock. The adapter provides no listening server, login, session cookies or credentials. It must be opt-in.

Only GET /processing/session and POST /processing/reconcile exist. POST has EXACTLY jobId, consumedRevision (integer >=3), and output (recover-stored or finalize-existing). There is no execution, lease, retry, no-output settlement, cleanup, object write/download, identity/grant administration, send or publication route. The accepted coordinator independently verifies current source/persisted bytes and actual ledger/output execution bindings. Finalization may commit immutable output metadata and completion in separate transactions; this never dispatches a new job or writes output bytes.

Policy fixes exact HTTPS origin, tenant/project, purpose and listed human owner manager IDs. Host incoming authentication supplies kind/id/current roles/scope/purpose/time and a 32–256 character session-bound random CSRF token. Authentication happens AFTER bounded POST input capture so a stalled body cannot retain an earlier authentication snapshot. The adapter rejects cross-origin/Fetch Metadata, unknown queries/fields/commands, and compares CSRF in constant time. Authentication metadata is a copy, auth method/configuration are captured at construction. The session response returns only CSRF plus local actor/scope; all JSON is private/no-store, same-origin and nosniff. Credentials/grants/source plaintext are not returned.

Actual uncompressed JSON UTF8 bytes are bounded to 16KiB and 4096 chunks. Separate default5s body/auth admission deadlines (10–30000ms) use cancellation AND monotonic admission/result gates, including blocked-JavaScript overruns and JSON decoding. Auth signals close on every exit. Failed bodies are cancelled without awaiting a hostile cancellation callback. Host server/proxy must still bound rejected bodies, rate/concurrency and connection lifetime. Trusted callbacks may ignore abort or perform effects; the adapter cannot preempt them or undo effects.

POST passes request cancellation and a default10s configurable10–30000ms stage deadline to the accepted coordinator. SQL/filesystem work already begun is AWAITED, never raced or automatically retried, and may outlive the request deadline. A durably acknowledged completion remains completed. HTTP200 contains completed plus exact private refs; HTTP503 with reconciliation-required and diagnostic phase is UNKNOWN, never rollback/absent effect/stopped proof or execution permission. Preserve exact execution/action and explicitly reconcile after fresh authentication/CSRF; never substitute a new execution or automatically switch recover-stored to finalize-existing. Replays still perform current policy/content checks.

Host authentication/identity proofing, TLS/reverse proxy/secure cookies/CSP, current authorization at the service gateway and refresh of captured manager policies remain required. No distributed permission fencing or atomic policy/storage/completion guarantee is claimed. Keep all real outputs private. This unit does not qualify deployed source/key/storage/identity, stopped/liveness/cleanup or browser/accessibility services.
