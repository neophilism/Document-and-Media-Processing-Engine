# Durable text-processing job ledger

`./text-jobs` uses the pinned Evidence SQL SDK in a dedicated processing operational database, never the Evidence engine database. Listed human managers submit exact text jobs or cancel unconsumed work. Listed service/agent workers obtain a purpose-bound lease and separately consume it before I/O. Expired unconsumed work can be re-leased with a new revision. Consumed work never becomes eligible again merely because a lease expires.

Consumption is deliberately not idempotently replayed as another permit. If the commit acknowledgement is lost, read current state and reconcile; do not execute from a read snapshot or call a processor based on a cached lease. Managers cannot recall consumed effects. Completion requires a mandatory bounded trusted outcome verifier and binds an exact derivative edition/hash and receipt edition; outcome and audit/outbox commit together. No source bytes, credentials, model output or model reasoning are stored in the queue.

The mandatory start verifier must establish current clean scan status, source bytes/hash/length, purpose authorization and source access. The mandatory outcome verifier must establish that the exact source/job profile produced the exact private derivative and that the receipt is authoritative. Neither callback may infer authority from caller strings or public availability. Host assertions are not authentication. Database state is scoped and immutable by revision; external permission verification is not an atomic fence across another service or processor.

This is queue/permit/outcome orchestration for the accepted UTF8 text processor only, not a daemon, byte fetcher, object store or processor runtime. A real worker must consume before acquiring bytes/performing I/O, call the existing exact-byte processor and store a private derivative/receipt through qualified services. Callback timeouts stop waiting, not callback side effects. Costs, quality, OCR/model dispatch, cancellation signals into running processors, network-session concurrency and deployment acceptance remain pending. Source purpose/clock/context and manager/worker identity must be supplied by trusted host authentication. A job snapshot is not an authentication credential.

Ten new integration groups use actual pinned migrations and a restricted PGlite login. They cover lifecycle/replay, lost consumption/completion acknowledgements, expiry/re-leasing, scope/purpose, bounded verifiers, authorization-time cancellation/expiry, simultaneous consumption and post-insert transaction rollback. They do not qualify independent database network sessions or live services; final-head CI is recorded separately in the PR.

The constructor also requires a trusted live clock function. Consumption samples that clock inside the final transaction after authorization and acquisition of the SDK project serialization lock, and refuses an expired lease or clock regression relative to the authenticated request time. `consumedAt` stores that sample. Audit timestamps otherwise retain authenticated request context and are not independent wall-clock attestations.

The host must replace a registry instance when deployment identity lists change; each instance captures its policy. Listed workers can read jobs in the same authorized project/purpose; this is not a finer case compartment system. Verifiers must be read-only, bounded/cancellable services and must tolerate a completed job when validating an exact completion replay. A timed-out verifier cannot commit an outcome through this ledger. Context and callback snapshots prevent caller mutation from changing a pending request, but do not freeze state hidden inside trusted callbacks.

This first ledger accepts successful private derivative outcomes only. Verified no-output/failure reconciliation and safe retry generations are not implemented: failed consumed work stays blocked. Guarantees are per job identity, not global deduplication of manager-created jobs. A host must not create a replacement job to bypass unresolved consumption. Before actual I/O the worker must also enforce its remaining runtime window and current policy; a permit consumed before expiry does not prove a lease remains valid after a delayed acknowledgement or that external permission cannot change.

## No-output reconciliation (implementation checkpoint)

`settleNoOutput(context, jobId, consumedRevision, proof, commandId)` adds a terminal `failed` state. Proof contains exactly a scoped receipt edition, a bounded failure reason, `processorStopped: true` and `noDerivative: true`. These fields are assertions until a trusted verifier validates them. A thrown exception, missing output observed at one instant or an expired lease is not proof that a processor cannot still complete.

A deployment may opt into `TextJobVerification.verifyNoOutput`; without it, reconciliation fails closed and old integrations retain their original behavior. The verifier receives the job, proof and exact consumed revision plus authenticated context and cancellation signal. It must establish final processor termination/quiescence and no committed or late derivative for that exact execution. Its strict true result is bounded by the existing verifier deadline. Workers can settle only their own purpose-bound execution; managers can reconcile scoped work.

Failure, exact receipt, immutable history, explicit audit event and outbox event commit atomically. Replay requires the same command and current identity/verification. `failed` cannot lease, consume, cancel or become successful, and creates no retry permit. Retry generations remain unimplemented. Source bytes, diagnostics and exception strings are not stored. Initial three integration groups pass; expanded recovery/race/timeout tests and final-head CI remain pending.
