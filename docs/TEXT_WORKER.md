# Single-job private UTF8 worker

`./text-worker` exports `runLeasedTextJob` over the actual `TextProcessingJobs` ledger. It consumes a current lease before invoking source or storage services. Only an acknowledged consume return permits source I/O; an uncertain acknowledgement never invokes callbacks. The runner copies exact source bytes, requires strict true processing permission and clean scan status, binds source edition/hash/length/language, then uses the accepted UTF8 extractor.

The host supplies authenticated context, trusted live clock and qualified source/private-storage callbacks. Storage must commit the private UTF8 **text bytes**, with derivative metadata and an authoritative receipt binding this exact job/consumed revision. Its returned hash must equal the extracted text hash, not a hash of JSON metadata. The ledger's mandatory independent outcome verifier still validates the final edition/hash/receipt before completion. The runner never provides proof-service implementations or trusts callback strings as identity.

One finite deadline and cancellation signal cover source/storage waiting and stage admission. Clock/lease checks run between stages. Database operations already begun are awaited rather than raced; an acknowledged completion remains completed if its SQL acknowledgement arrives after the deadline. All failure results are sanitized and conservatively request reconciliation, including unknown consumption acknowledgement. A null consumed revision means no acknowledged execution edition, not proof of rollback. No automatic retry, no-output settlement, daemon or discovery loop is added.

Timeouts stop acceptance and later stages, not arbitrary callback side effects or blocked JavaScript. In particular storage may commit after a timeout. Such work remains consumed/unresolved until separately verified. A host must not create replacement IDs or re-execute from snapshots, and must enforce current policy at source/storage gateways. This reusable runner is not process isolation, a transferable permit or globally exactly-once processing. Real object/receipt/liveness services, OCR/model workers, cost/quality and deployed acceptance remain pending.

Initial tests use the actual restricted migrated PGlite ledger and controlled callbacks; no live network, private input or real object storage is involved. Broader review and final-head CI are pending at this checkpoint.
